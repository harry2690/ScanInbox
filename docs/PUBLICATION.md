# 原始碼公開前檢查

這份清單適用於尚未建立 Git 儲存庫、準備第一次公開原始碼的狀況，不會自行初始化 Git、提交或上傳。

## 資料分層

| 資料 | 應存放的位置 | 是否提交 |
|---|---|---|
| App 功能預設，例如接收埠、紀錄天數 | 程式碼及公開範例 | 可以，不含個人資料 |
| 使用者的印表機 IP、別名、輸出資料夾 | 使用者 Application Support 內 settings.json | 不提交 |
| 掃描文件、接收紀錄、診斷與封包 | 使用者資料夾與程式資料目錄 | 不提交 |
| 開發用個人設定 | config/*.local.json | 不提交；只提供 *.example.json |
| 發佈簽署身分及鑰匙圈設定檔名稱 | config/release.local.json | 不提交 |
| 私鑰、密碼、Apple 公證憑證 | 鑰匙圈或機密儲存空間 | 不提交，也不放在普通 JSON |
| App、ZIP、編譯快取與 dSYM | dist、.build | 不作為原始碼提交；發佈附件另行審查 |
| 第三方套件原始授權 | Receiver/vendor | 保留並提交 |

App 不從儲存庫自動讀取個人的 *.local.json。執行設定仍由 App 讀寫使用者的 Application Support；發佈設定只有打包命令明確指定時才讀取。

## 檢查重點

- 原始碼沒有預填實際使用者、組織、印表機 IP、Windows 接收端、絕對家目錄路徑或電郵。
- 初次啟動的印表機清單為空；既有使用者的 settings.json 不因公開前整理而改寫。
- 公開範例以空值、空清單或文件用示意位址呈現。若建立開發用私有設定，檔名須符合 *.local.json 的忽略規則。
- .gitignore 排除憑證、私鑰、.env、掃描資料、封包、日誌、SQLite、建置產物與編輯器個人狀態。它不會加密檔案，也不能阻止未來刻意強制加入。
- dist 內舊版 App 即使已被忽略，仍可能含有舊預設或簽署身分；分享前從整理後的原始碼重建，不直接公開舊檔。
- 不把 Apple 帳號、密碼或 .p8／.p12 內容放進命令範例、JSON、截圖或 CI 日誌。
- 若後續引入 CI，使用服務的 Secrets 或其他機密儲存機制，不把憑證寫進工作流程。工作完成後移除暫存憑證與鑰匙圈。
- 正式簽署 App 的憑證持有人與 Team ID 可被查詢。若希望不公開這些身分，應先決定發佈策略，不能只靠忽略規則處理。
- README、LICENSE 與套件授權一致。專案為個人非商業授權，不標示為 MIT；第三方授權完整保留。

## 可提交範圍

Sources、Receiver 的程式與 vendor、Scripts、Tests、config/*.example.json、README、docs、AGENTS、LICENSE、THIRD_PARTY_NOTICES 及 .gitignore。

只將實際需要的檔案納入未來儲存庫，避免直接打包整個工作目錄。若日後曾將機密提交，即使之後加入忽略規則，舊版本仍可能保留，應另行處理歷史與憑證撤換。
